# How quickly each window action answers (0.3.3)

Generated by `LargeVaultResponsivenessTests` (tests/Armory.EndToEnd.Tests), requirement E and
feedback N6: a mentor's computer holding a 1,500-file synced vault, the school network
(`LatencyProfile.School`: 60 ms a database call, 250 ms to sign a transfer, 60 ms and 4 MB/s
to file storage), the open-files question costing what it cost on Windows (10 seconds were it
asked about all 1,500 read-only files, a fifth of that a file for files checked out here), and
the sync loop running as it does in the app. Each action must answer within 1 second plus the
server calls and transfers made meanwhile and the open-files questions it asked about its own
files (their times added up; each question is bounded by the engine's 2 second budget), and say
what it is doing in the window's running lines within half a second. The window itself marks the
pressed key busy the moment it is clicked, before the host hears of it. The test file system
reuses a file's hash while its size and last-write time are unchanged, as the Windows scan does.

Measured 2026-10-09 on Unix, 4 processors, with the portable test file system.
To make it again, from the repository's root, with a throwaway PostgreSQL cluster:

```
ARMORY_TEST_POSTGRES="Host=127.0.0.1;Port=<port>;Username=postgres;Database=postgres" \
ARMORY_RESPONSIVENESS_REPORT=docs/agent/responsiveness-0.3.3.md \
dotnet test tests/Armory.EndToEnd.Tests --filter FullyQualifiedName~LargeVaultResponsivenessTests
```
