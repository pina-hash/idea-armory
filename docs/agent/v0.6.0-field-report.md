## Why 0.5.9 did not reach the computers

A tag is not an installer release. The v0.5.9 tag exists, but GitHub has no published
v0.5.9 release or assets. The latest published release at inspection was v0.5.8.
[Agent release run 42450984059](https://github.com/pina-hash/idea-armory/actions/runs/42450984059)
failed in the Windows PowerShell 5.1 retirement-path regression before packaging. Its
bad-path case containing a null character was accepted: .NET Framework's Windows
ExpandEnvironmentVariables can truncate a string at NUL before the subsequent path
validation sees it. The source now rejects control characters before expansion. The
regression keeps all old cases and adds leading and trailing NUL cases. No rejected
filename is repaired or guessed, and the real retirement safety/installer checks remain.

[Window run 42450984030](https://github.com/pina-hash/idea-armory/actions/runs/42450984030)
also failed the first-run reading check on two Trash help strings. The help now uses
shorter words; the reading limit was not relaxed.

Consequently there is no evidence of 0.5.9's faster update retries or retirement fix
reaching any computer. A successful download of 0.5.8 is evidence for the older updater,
not for 0.5.9. 0.6.0 carries the fixes forward and uses the same tag-triggered Agent release
workflow, including Windows tests, installer upgrades, retirement safety and Velopack feeds.

## File-move and picture boundaries

The bridge names path, selected file ID, project ID and destination folder. The engine
refreshes before checking that identity, refuses a different project, a nonexistent or
invalid target, an archived project, an open file, another computer's check out, unsent
work and an occupied destination. A move never implicitly force checks in another person.
The existing PendingMove journal/state path supplies receipt replay and reconciliation.
The existing armory_move_file RPC checks both source and destination class-folder writers.
The permission regression uses that 0319 SQL body verbatim in the throwaway database,
with the existing minimal roster fixture. No new production SQL or endpoint is needed.

An internal drag only comes from this page's remembered source. Foreign text or a forged
DataTransfer is not interpreted as a path. External File Explorer drops retain their copy-in
behavior. Tiles and condensed folders retain virtualization, roving keyboard focus and
44-pixel controls; shared empty folders remain visible to students and admins.

STEP pictures depend on a Windows STEP thumbnail provider. The existing single STA queue,
64 waiting requests, five-second answer limit, stuck-provider watchdog and cache bound
remain. With no provider the old, named information tile remains. General STEP geometry,
interactive 3D and automatic installation of a STEP preview tool are outside this release.
The managed STL, DXF, G-code, SVG and LightBurn renderers are unchanged.
