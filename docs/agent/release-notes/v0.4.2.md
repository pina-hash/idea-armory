## What's new in Armory 0.4.2

Computers on 0.4.1 update to 0.4.2 by themselves. Computers still on 0.3.1, 0.3.2 or 0.3.3 need `IDEAArmory-win-Setup.exe` run once, from this release; it keeps your Armory folder, your files and your sign-in.

**Your Armory folder can't be a project folder any more.** If you pick a project folder (or a folder inside one) as your Armory folder in Settings, Armory uses the folder that holds your projects instead and tells you so. A computer that already has its Armory folder inside a project folder stops syncing there and shows one card with **Fix it**. Fix it moves Armory back to the right folder and puts every file where it belongs: copies that are the same become one, nothing is uploaded twice, and nothing you changed is lost. If a file was changed in both places, the newer copy stays and the older one is kept in a "kept copies" folder beside your Armory folder. If SolidWorks still has a file open, Fix it says so; close it and click Fix it again.

**One card for a thousand files.** Files outside every project now get one card ("1,498 files are outside every project") with one sentence and one button, **Open the Armory folder**. Every card's list now reaches every file, not just the first 200, grouped by why, with the count on the button matching the card.

**Open from the website.** A file's page on ideabosco.com has **Open in SolidWorks**. It opens the file through Armory on your computer, the same way Open does in Armory: read-only unless you have it checked out. It never checks anything out by itself.

**A calmer log and "What Armory is doing".** A file SolidWorks keeps open is written in the log once, not every few seconds, and Armory checks on it less and less often while it stays open (it still goes up the moment SolidWorks lets go). "Asking Armory what changed" shows once instead of filling the panel. A new SolidWorks part that isn't saved yet is named in the log instead of showing a blank.

**Fewer false alarms.** Signing out of Windows on a lab computer is no longer reported as a crash. A pass that moved a lot of files is judged by how many it moved, not only by how long it took.
