## Reliability

| Item | Found | Built |
| --- | --- | --- |
| False `serverOutage` incidents (about 250 from 0.6.0) | `GlitchDetector` filed an outage at the first failed pass. Lab computers wake about every 30 minutes, and the first passes after a wake fail with "No such host is known". The engine's first retry after that came 30 seconds later, and the marker that remembers an outage was set on the first failure. | An outage is an incident only after 3 minutes unreachable while awake and on a network, measured from the last wake or network return; failures while asleep or with no network never count; a gap over 10 minutes between failures starts the measure again. The marker is written with the incident. The engine retries every 5 seconds for 2 minutes after a wake without growing its offline wait (`SyncEngine.Resumed`, also from the watch's `frozen` gap and from Windows' network events). The update check does the same (`Updates.AfterFailure`). docs/agent/TELEMETRY.md, ENGINE.md, INSTALL.md. |
| `retireFailed` on shared lab computers | Three writers of `install-retirement.jsonl` (the app, `Retire.ps1`, `AfterUpdate.ps1`) each used `AppendAllText`, which fails at once when another has the file open, and under `$ErrorActionPreference = 'Stop'` one failed line ended the whole inventory. The "invalid inventory target BthUdTask.exe / sc.exe" lines were Windows' own programs named without a folder, logged as deferrals, and the last of them became the incident's reason. Each start filed another incident. | Writers take turns for up to 3 seconds and never throw; readers share. Program names with no folder are skipped silently. The incident is filed once per version until a cleanup finishes (`RetireNotice`). docs/agent/INSTALL-OWNERSHIP.md, "0.6.1". |
| 0.3.2 and 0.3.3 that never updated | They have no updater. Where the cleanup always failed (the bug above), the old copy rewrote the sign-in Run entry to itself, every launch of the newer copy handed off to it (`LaunchFlow`), and the newer copy never ran long enough to update. Their 6,473 s to 43,009 s "passes" are the 0.3.x clock counting through sleep (fixed in 0.4.0). | The cleanup fix ends the loop for any computer whose newer copy is 0.6.1. Nothing reaches a computer that only runs 0.3.x: the setup must be run there once (release notes, "For Mr. Pina"). |
