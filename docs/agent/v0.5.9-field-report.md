## Changes

Retirement now validates untrusted registration, task and shortcut paths before path APIs
or ownership comparisons. It expands environment variables and normalizes surrounding
quotes and whitespace. It defers and audits command wrappers and malformed targets rather
than stripping filename characters or guessing another file. Files, unknown payloads,
protected vaults, changed payloads and linked data retain the existing safety rules.

`tools/test-retirement-paths.ps1` reproduces the real logged path shape. It failed before
the fix and passes after it, including a valid Armory target following a malformed target.
The packaging action runs this under Windows PowerShell 5.1. The existing real-disk
retirement safety and installer cycles remain in the release workflow.

Update checks use a one-shot timer: after failures, retry in 1, 5, 15, 60 and then 240
minutes. A successful check returns to four hours. This addresses startup DNS/network
failures costing a whole class period. It cannot rewrite a binary that never starts.

The existing server retry schedule remains. A server outage now emits at most one
`serverOutage` incident until a pass reaches the server again. Slow passes and slow actions during
the outage do not become additional incidents. An atomic `server-outage.active` marker
keeps that state across restarts; delayed older writes cannot overwrite a newer recovery.
Disk errors and actual fatal exceptions retain their own reporting.

The native file page offers Move to Trash when the file is available. It requires typing
remove. The engine refuses open files, checkouts, archived projects and work still being
sent, checks the selected file ID after refreshing so a reused path cannot remove a replacement, then asks the existing `armory_web_trash` RPC, which enforces membership and class
folder ownership too. Tombstone reconciliation preserves bytes and moves copies to recovery.
Lost acknowledgments are reconciled without another tombstone. Restore is on the project's
website, `/armory/<project-id>/trash`; the 30 days limit that restore action, not retained
version storage. No permanent-delete or blob-purge behavior was added.

Sort files uses the existing shared version's `UpdatedAt`, in folders and filtered search
results, with natural filename ties and undated files last. It does not pretend a local
unshared save is a team version.

Shared empty folders use the additive contract in `server/optional/007_v059_shared_folders.sql`.
It carries no file contents or placeholder file. Writes delegate existing folder permissions,
checkout refusals and receipts. A change-feed trigger keeps metadata aligned when older
agents or the website rename, delete or purge folders. The app validates names through
VaultPath, creates folders only after remote folder moves, and keeps them through cleanup.
The companion website migration is `supabase/migrations/0410_armory_shared_empty_folders.sql`, applied through idea-app's existing numbered migration workflow. Its admin incident view also explicitly flags names used by multiple machine IDs in the loaded reports.

## Mr. Pina's one-time step

1. From the **v0.5.9** release, download **IDEAArmory-win-Setup.exe** to the top of a flash
   drive. Use that exact name, the installer with no hyphen between IDEA and Armory.
2. At each of the three computers listed above, sign into the Windows account that normally
   uses Armory. That is the IDEA account on shared lab computers; use Mr. Pina's own account
   where that is the normal account.
3. In **File Explorer**, open **This PC**, open the flash drive, and double-click
   **IDEAArmory-win-Setup.exe** once. If Windows shows the unsigned-app prompt, use
   **More info**, then **Run anyway**, as the existing install instructions describe.
4. Let Armory open. In **Settings**, check **About this Armory** says **0.5.9**. The setup
   keeps the Armory folder, saved files, settings and sign-in; do not uninstall first or
   delete any team folder. It needs no administrator password.
5. For a computer whose app already runs and says an update is ready, **Quit** from the
   tray, then open **IDEA Armory** from Start to apply it. Merely closing its window leaves
   it in the tray. If it cannot open, use steps 1 to 4.

Repeated GitHub DNS failures need the school's network access restored; neither an installer
nor an Armory update can repair DNS. No Defender setting was changed. Renaming duplicate
Windows names is optional for readability, using the existing `docs/LAB_COMPUTER_NAMES.md`
steps; it is not required for correct locks or computer identity.

## Validation and limits

The locked restore and warning-as-error build passed. The final full native suite passed
1,568 tests, with 121 Windows-only tests skipped on Linux (1,689 discovered, 0 failures).
Both 10,000-scenario simulations passed, in about 92 and 96 seconds, under their unchanged
two-minute limits. The retirement path script passes its boundary checks without inventorying or changing this computer; the
packaging action also runs the real rejected-path check under Windows PowerShell 5.1.

The full initial page sweep measured 340 pages with 0 target-size, network, contrast,
keyboard, overflow, jargon or em-dash failures. It caught old action-list expectations and
an extra toolbar row, which were corrected. The final focused sweep measured 20 affected
pages, 121 passing functional flows, all 49 bridge message types and 75 passing shape checks.
The isolated drawing checks all pass: ten large-view updates took 2,937 ms against the
unchanged 3,000 ms budget; unchanged 0.5.8 took 2,710 ms on the same host. Overlapping these
timing checks with simulations caused earlier timing failures, so the final comparison ran
after the native suite. Sort, shared empty folders and Trash were also driven directly at
1280 and 420 pixels, including the selected file ID, confirmation, refusal and success.

The companion repository records its whole-suite results and migration application in
`docs/history/codex-armory-0-5-9.md` and the existing `docs/migrations-applied/` records.
The unchanged release workflow performs Windows packaging and installer cycles before it
publishes assets. Its results and the final assets are on the v0.5.9 release and Actions pages. Core rules,
simulation invariants and `tests/GUARDS.txt` are unchanged. New behavior has regression
coverage in FileActionsTests, GlitchRuleTests, IncidentTests, UpdatesTests, the retirement
path script and the real page's browser checks. The established safe-replacement concurrent
external-writer limitation in `docs/platform/safe-replace.md` remains explicit.

Not verified on actual Windows lab hardware: school policy and DNS, SmartScreen on a lab
account, installed-copy discovery, real taskbar pins, mouse side-button delivery through
WebView2, SolidWorks open/save handles, DPAPI sign-in retention and an automatic update
through a real lab reboot. Windows CI installer and platform checks are separate evidence,
not a lab-hardware claim.

Deferred optional work: a tiles/grid view, internal drag and drop for reorganizing files,
condensed admin folders and geometric STEP thumbnails. External drops into the open folder,
the existing preview formats and mouse navigation remain available.
